# Coding standards

Read nearby code first and follow its naming, component structure, styling approach, and import conventions. Keep components purposeful and make state ownership explicit. Prefer clear code over speculative abstractions.

Make the smallest patch that solves the request. Do not reformat unrelated files, add dependencies, or alter configuration without a stated need. Use semantic controls for interactive behavior, give images meaningful alternatives when they convey content, and avoid hard-coded secrets or environment-specific values.

Before handoff, inspect the diff for unused imports, dead paths, inconsistent loading/error states, and accidental behavior changes.
